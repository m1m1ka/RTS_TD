# 周五保卫战 · Friday Defense

一个 Three.js 格子 RTS + 塔防游戏 Demo。守护森林中最后一台「下班打卡机」，击退从不同出生点涌来的加班大军。默认六天，每天两波，全部守住即可准时下班。

全屏游戏画面，最顶部为当天波次进度条，左右显示核心血条与持牌数。出生点仅保留地面标记；战斗开始后隐藏开始按钮，不显示额外的波次、敌人数和状态文字。底部为四类手牌，等级以与血条数字相同字体的白色 lv 文本显示在英雄单位框左上角，已装备物品图标显示在血条上方。操作说明收进「?」。

## 启动

需要 Node.js 20.19+ 或 22.12+。

```sh
npm install
npm run dev
```

访问终端显示的本地地址。Windows PowerShell 如果限制执行 npm.ps1，请使用 `npm.cmd install` / `npm.cmd run dev`。

```sh
npm run build
npm run preview
```

生产产物位于 `dist/`，可以部署到静态托管服务。字体使用可选的 Google Fonts，网络不可用时回退系统字体；游戏贴图均在本地程序化绘制，没有外部图片依赖。

## 操作和玩法

以下为默认规则；可在独立配置页修改。

- 点击英雄或 `1–9` 选择；重复点击取消选择，点击空地自动寻路，`WASD / 方向键` 下达单格移动。成功下达路线后自动取消选择，单位继续沿路线移动；英雄卡放置后不自动选择。
- 点击英雄、炮台或敌人，左侧显示名字、图标、当前 / 最大生命、攻击力、攻速和攻击距离。攻速保留一位小数，其余为整数；升级、装备和受伤后实时更新。
- 战场默认放大；滚轮以鼠标位置为中心缩放（全图视角的 1～3.2 倍），拖动平移视野，`0 / Home` 返回全图。手机支持单指拖动、双指缩放；轻点仍用于选择和移动。
- 战场没有树木障碍，原障碍格也可移动、部署。单位沿四个正交方向移动，攻击距离按曼哈顿距离计算。选中英雄时，无边框的半透明绿色格子显示可达空地，排除核心和其他单位占据的格子；取消选择时同步隐藏。
- 顶部波次进度条以交叉剑标记每波的起点，从当前节点向下一节点按击杀进度填充；交战中的节点亮起，完成节点变绿。最后一段通向灰色旗帜，当天全部波次完成后旗帜变绿。波次较多时可横向滚动，并自动跟随当前波次或通关旗帜。
- 阿蓝负责近战扛伤，小叶负责远程射击，咕咕的法术对目标相邻敌人造成 55% 溅射伤害。
- 战士挥刀并产生刀光，弓手射出实体箭矢，法师释放魔法弹与爆环，炮台发射咖啡弹，敌军使用爪击。伤害在挥击或弹体命中后结算。
- 弓、法杖和咖啡炮管为独立装备，通过单位的 `weapon` 字段配置，与角色 `type` 外观分离。武器自动转向目标，弹体从弓前端、杖尖或炮口发射，并有拉弓、蓄能、后坐反馈；敌我双方共用这套装备机制。
- 所有单位及打卡机拥有受击闪白、方向性轻震、挤压回弹与命中火花；单位血条带损血拖尾、死亡带淡出动画。法师施法/受击时短暂显现魔法盾（视觉反馈，不额外减伤）。暂停及倍速统一作用于战斗和动画。
- 战场血条使用粗黑框、红色填充与白色生命数字。玩家英雄和炮台常驻显示；敌人受击后显示 2.4 秒，重复受击刷新时间，损血带红条缓降和延迟拖尾，最后淡出。
- 敌人受击产生少量暗酒红色溅血；死亡时有短促的定向喷射，致命一击不叠加普通受击溅血。在死亡格子留下本局持续存在的暗色血迹，重开时清除。
- 每个单位有生命、攻击、攻击范围、攻击频率；炮台自动攻击，敌人按各自速度逐格前进。
- 拖拽卡牌至战场使用；也可以先点卡牌，再点目标。无效目标不消耗卡牌，`Esc` 取消选牌。滚轮或左右箭头查看更多牌；拖拽使用绿色虚线贝塞尔箭头指示有效目标，无效目标显示暗红色。
- 英雄牌：在内部空格放置可操控英雄；消耗一张持牌，英雄持续留在战场，阵亡后每波结束归队。同种英雄可以拥有多个。
- 猫女「米娅」：初始手牌新增一张，生命 230、攻击 24、射程 1、攻速 1.8、移速 6，使用近战爪击。卡牌 icon 和实际使用 icon 均可选择内置 `catgirl`（猫女 · 米娅）；棋子自动套用青绿色底框。形象由 `src/art.js` 使用与其他英雄一致的几何色块、粗描边绘制，随项目部署，可跨设备导入配置使用。旧配置仅补入一次，后续主动删除或修改会保留。
- 资源牌：实战心得使英雄等级 +1，生命与攻击按该英雄的等级公式成长，并恢复最多 100 生命；升级不会自动增加攻速。热咖啡恢复单个英雄 120 生命；炮台牌放置自动咖啡炮台。炮台不能堵死核心道路。
- 战斗牌：战斗中即时使用。火球对曼哈顿半径 1 内敌人造成 110 伤害；落雷单体 240 伤害；寒霜半径 2、45 伤害，并降低移动速度 55%，持续 3 秒。
- 装备牌：拖到英雄身上永久装备，不重复装备同一物品。鹰眼箭袋攻击 +8 / 射程 +1；疾风徽章攻速 +25%；饮血吊坠攻击吸血 15%；守护护符减伤 25%；星辉法杖替换武器为法杖、射程至少 3，并获得法术溅射。英雄外观不变。
- 持有多少牌就能用多少牌，无能量、抽牌、弃牌或回合出牌次数限制。资源牌与战斗牌用后消耗；英雄和装备从手牌转化为战场上的持续单位或效果。未用的牌跨波次保留。
- 顶部旗帜开始当天，默认等待 3 秒开始第一波。之后每波全员出齐且最后一个敌人死亡即结束，按下一波配置的等待秒数自动开波（默认 5 秒）；出生点还有独立的波内出兵延迟。等待和出兵计时均随暂停、倍速变化。
- 每天最后一波胜利后游戏暂停，三选一卡组奖励：战地补给、火力支援、精锐增援。领取后立即加入手牌，每天只选一次，最后一天也有奖励。每波结束仍恢复存活英雄 25% 最大生命，阵亡英雄以 50% 生命归队；领取当天奖励后可用顶部旗帜开始下一天。
- `空格` 暂停，顶部 `1× / 2×` 调速，可切换合成音效、查看帮助和重新开局。
- 第六天出现「周五临时需求」首领。核心生命归零失败，击退全部 101 名敌人胜利。最佳击退数保存在本机浏览器。

## 开战机制

「开战」指玩家点击顶部「迎战」。在倒计时和刷怪之前，依次结算场上存活英雄的开战规则；自动切换波次、部署新英雄、保存配置不会重复触发。

默认英雄规则：

- 阿蓝：开战等级 +1；每有一位英雄触发开战效果（含自身和额外触发），自身移速 +0.5 格/秒。
- 小叶：开战为自身和最近一位其他英雄增加 0.2 次/秒攻速。
- 咕咕：开战额外触发最近一位其他英雄的全部开战规则一次。

等级永久保留，默认攻速和移速加成只持续当前天，当天结束时清除。距离按曼哈顿格数计算，同距离选择更早部署的英雄；阵亡英雄和炮台不参与。每位英雄的正常开战独立发起连锁，同一连锁中每位英雄最多响应一次，避免互相回响无限循环。监听效果本身不会自动生成新的开战事件。

配置页 → 卡牌配置 → 英雄牌 →「触发机制」，可增删、复制、排序、停用规则，或使用四种快捷模板。每条规则独立配置触发事件、事件来源、监听距离、作用目标、目标距离、最近英雄数量和多个后续效果。距离 -1 表示全场；目标支持自身、近邻、自身与近邻、范围内全体英雄和事件来源英雄。效果支持升级、治疗、属性加法/倍率及额外触发，属性加成可选择当天或永久持续。保存只改变下一次触发时使用的规则，不追溯修改已经结算的结果，也不会重复叠加。

旧配置缺少 `triggerRules` 时自动补齐现有三位英雄的默认规则；显式设置空列表表示无规则，会被保留。规则随 JSON 配置导出和迁移。

## 规则工坊与配置迁移

游戏右上角的齿轮打开 `/config.html`，配置页和战场可同时打开。

- **卡牌配置**：按英雄、资源、战斗、装备分类，支持新增、复制、删除。名字、描述、卡面 icon 与实际使用 icon 分开设置；PNG / JPEG / WebP 图片会缩放并内嵌进配置。英雄与炮台可配置生命、攻击、攻击距离、攻速、移速和独立武器。
- **效果组合**：升级、治疗、属性增加或倍率、伤害、减速、吸血、减伤、武器替换、攻击溅射、放置炮台。每项效果拥有独立数值；伤害与减速可分别配置作用半径。等级先计入基础成长，再叠加永久属性效果与装备。单次治疗和升级不会因同步而重复触发。
- **英雄触发规则**：与使用卡牌时的即时效果分开编辑，触发事件、监听范围、目标筛选、作用范围与效果数值可自由组合；默认四种开战模板已接入现有英雄。
- **等级公式**：各英雄、敌人独立设置 `levelGrowth.maxHp` 和 `levelGrowth.atk`，按「1 级基础值 + 每级增量 ×（等级 − 1）」计算，再叠加装备或波次倍率。配置页实时预览 1、5、10 级数值。旧英雄继承原全局成长，旧敌人成长为 0。保存时按当前等级重算并保留生命比例，不重复叠加。
- **初始默认**：每天第一波开始等待秒数、初始手牌、核心生命、升级治疗、波后治疗和复活比例。攻速仅由基础配置与明确的卡牌、装备、触发效果决定。
- **敌人等级**：每个出生点的出兵条目可独立设置等级（1～999，默认 1），同类敌人可以在不同波次、不同出生点使用不同等级。先算等级属性，再乘波次生命 / 攻击倍率并四舍五入；已开始波次的出兵等级保持不变。
- **敌方单位**：新增、复制、删除敌人，配置外观图片、基础属性和武器。
- **天数与波次**：按天管理关卡和胜利奖励，每天支持多波，天和波均可增删、复制、排序。每波配置生命/攻击倍率、上一波结束后的等待秒数。在 15×11 格子图中选择出生点，各点配置波内延迟、逐个出兵间隔、敌人类型及数量列表；总数自动计算。出生点堵住会原地等待，不会换点；仍有未出场敌人时不会提前结算。

计时示例：第二波设置等待 5 秒，某出生点设置延迟 3 秒。第一波最后一名敌人死亡 5 秒后，第二波开始；再过 3 秒，该点出现第一名敌人，随后按该点间隔依次出兵。敌人配置列表可以混合多种类型，按列表顺序生成。

保存配置后，尚未开始的波次和等待时间同步更新；已经开始波次的出兵计划保持不变，避免重复生成或漏刷。需要立即替换当前波时选择「保存并重开」。单位基础属性、卡牌和装备仍实时同步。

“保存并同步”先校验再保存到当前浏览器，立即通知同一来源（协议、地址、端口相同）的游戏页面。已部署单位按当前生命比例更新属性，手牌展示、装备效果与图标、敌人属性和后续生成规则实时更新，未出牌的备战局会同时更新初始手牌。已进行的游戏保留剩余持牌数、升级和消耗记录；“保存并重开”清空当前局并完整应用新初始规则。已经发出的攻击按发射时的数值结算。

**迁移到另一台设备**：导出 JSON 文件，在另一台设备的配置页导入，再点击保存。文件包含全部规则和上传图片，不依赖旧电脑的文件路径或图片外链。导入先进入草稿，不会自动覆盖正在使用的规则；保存后刷新仍然生效。此 Demo 使用浏览器本地持久化与同源页面同步，不依赖云端账号或服务器数据库；不同设备通过导入/导出迁移。构建产物同时包含游戏与配置页面。

配置采用版本 2，支持最多 100 张卡牌、50 种敌人、100 天、每天 100 波，每波最多 40 个出生点和 500 名敌人。版本 1 的本地存档和导入文件自动迁移为「每个旧关卡对应一天、当天一波」，保留敌人数量、类型、出生分配、倍率、卡牌、图片和奖励。保存/导入会校验数值范围、效果枚举、卡牌和敌人引用、可达出生点、初始英雄及图片格式。上传图片单张不超过 5 MB，自动缩小至最长边 256 像素；整份配置限制 3.5 MB，保存失败时保留草稿并可导出备份。

## 实现

- `src/art.js`：手绘风 Canvas 贴图、棋盘灌木和森林背景。
- `src/game.js`：独立战斗模拟、BFS 寻路、卡牌使用校验、装备效果、波次和奖励结算。
- `src/main.js`：Three.js 正交场景、单位插值、弹道和伤害飘字、输入和界面。
- `src/combat-vfx.js`：职业弹体、刀光、魔法盾、命中粒子与特效生命周期。
- `src/health-bar.js`：参考图风格的数字血条、受击显隐和损血缓降。
- `src/weapons.js` / `src/weapon-rig.js`：装备定义、独立武器贴图、转向、发射点和后坐动画。
- `src/cards.js`：当前配置中的卡牌与初始手牌绑定。
- `src/config/defaults.js`：可迁移规则的默认数据。
- `src/config/schema.js` / `store.js`：枚举与校验、持久化、跨页面同步。
- `src/config/editor.js` / `editor.css` / `icons.js`：规则工坊、上传图片和预览。
- `src/card-ui.js` / `src/card-art.js` / `src/cards.css`：手牌、鼠标与触摸拖拽、插画、奖励界面。
- `src/style.css`：响应式游戏 HUD。

使用 Three.js [OrthographicCamera](https://threejs.org/docs/pages/OrthographicCamera.html) 与 [CanvasTexture](https://threejs.org/docs/pages/CanvasTexture.html) 在 WebGL 中呈现俯视插画风格，角色、棋盘和特效是 Three.js 场景对象。

## 验证

```sh
npm test
npm run test:browser
npm run test:config
npm run build
```

浏览器检查自动启动独立测试服务器。Windows 优先使用已安装的 Chrome 或 Edge，也可通过 `CHROME_PATH` 指定浏览器；其他环境先运行 `npx playwright install chromium`。截图输出到 `logs/cards-desktop.png`、`logs/cards-battle.png`、`logs/cards-rewards.png` 和 `logs/cards-mobile.png`。

配置测试包含组合效果与热更新、真实页面编辑、上传、跨标签同步、新局应用、在全新浏览器环境迁移（含图片）、刷新持久化、非法文件与数值拦截。配置页截图在 `logs/config-cards.png`、`logs/config-waves.png`、`logs/config-mobile.png`。

开发模式提供 `window.__game` 供自动化测试读取状态和推进模拟；生产构建不暴露测试接口。
